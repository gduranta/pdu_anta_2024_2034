1. Fundamentos Arquitectónicos del GeoVisor

El GeoVisor del Plan de Desarrollo Urbano de Anta (2024 - 2034) está desarrollado sobre el motor analítico R Shiny con soporte espacial de alto rendimiento (bibliotecas compiladas en C/C++: GDAL, GEOS y PROJ vinculadas al paquete sf).

A diferencia de un sitio web estático tradicional (HTML/CSS), un GeoVisor reactivo opera mediante un proceso servidor activo que mantiene un socket de comunicación bidireccional (WebSocket) con cada ciudadano conectado para realizar en tiempo real:

  • Intersección geométrica puntual: Localización del lote mediante coordenadas UTM 18S (WGS84) o GPS móvil frente a los 3,664 polígonos zonificados del PDU.
  • Análisis de afectaciones viales: Búsqueda espacial de proximidad con los 1,673 tramos viales, secciones normativas y áreas de afectación.
  • Generación dinámica de certificados: Compilación en memoria y descarga de la Ficha Informativa de Zonificación Oficial con código QR de verificación.
  • Validación de acceso ciudadano (Estilo SUNARP): Control temporal de 10 minutos por sesión y tope de 2 periodos diarios por DNI según la Directiva de Seguridad de la Información (Ley N° 29733).

2. Requisitos Técnicos para Depositar la Aplicación en el Servidor Municipal (Dossier OTI)

Para que el equipo de la Oficina de Tecnologías de la Información (OTI) o el área de Sistemas de la Municipalidad Provincial de Anta aloje e implemente formalmente el GeoVisor en la infraestructura institucional (física, virtualizada o en la nube), el entorno de hospedaje debe cumplir con el siguiente pliego de condiciones técnicas:

2.1 Requisitos de Hardware y Capacidad de Cómputo

Las capas cartográficas (3,664 polígonos zonificados y 1,673 ejes viales) se cargan e indexan en la memoria RAM del servidor para ofrecer respuestas inmediatas a las consultas ciudadanas sin depender de llamadas lentas a bases de datos externas.

Recurso Requisito Mínimo Requisito Óptimo Recomendado Finalidad Técnica
Entorno Servidor Físico dedicado o VM Máquina Virtual dedicada (VMware / Proxmox / Hyper-V) Aislamiento operativo y facilidad de snapshots/backups.
Procesador (CPU) 2 vCPU (x86_64 @ 2.2 GHz) 4 vCPU o superior Cálculo de intersecciones geométricas y generación de PDFs.
Memoria RAM 4 GB libres garantizados 8 GB a 16 GB de RAM Retención de capas Shapefile en memoria y concurrencia.
Disco Duro 30 GB libres (SSD SATA) 60 GB libres en SSD NVMe Lectura ultrarrápida de capas y almacenamiento de logs de auditoría.
Energía / Contingencia Red municipal con estabilizador Conexión a banco de baterías UPS institucional Garantizar continuidad ante cortes eléctricos intempestivos.

2.2 Requisitos de Software y Dependencias de Sistema

El servidor municipal debe contar con el siguiente stack de tecnologías instalado y configurado:

  • Sistema Operativo Homologado:
    • Linux (Estándar OTI): Ubuntu Server 22.04 LTS o 24.04 LTS (64 bits) / Debian 12.
    • Windows: Windows Server 2019 / 2022 o Windows 10/11 Pro (64 bits).
  • Motor Analítico Base: R versión 4.3.0 o superior (actualmente probado en R 4.4 / 4.6.1 x64).
  • Librerías C/C++ Geoespaciales Mandatorias (Nivel Sistema Operativo):
    • GDAL >= 3.4.0: Motor de lectura, reproyección y parsing de formatos GIS (Shapefile, GeoJSON, KML).
    • GEOS >= 3.10.0: Motor de topología y cálculo de intersección espacial vectorial (detección de lotes dentro de zonas urbanas).
    • PROJ >= 8.2.0: Transformación de sistemas de coordenadas geodésicas (Datum WGS84 EPSG:4326 a UTM Zona 18 Sur EPSG:32718).
  • Paquetes R Requeridos (Instalados en la biblioteca global del servidor): 
    # Comando de verificación e instalación en R:
install.packages(c("shiny", "bslib", "leaflet", "sf", "DT", 
                   "htmltools", "scales", "RColorBrewer", "digest"))

2.3 Requisitos de Red, Puertos y Soporte Mandatorio de WebSockets

Requisito Crítico de Conectividad (WebSockets): El cortafuegos (Firewall / UTM Fortinet / pfSense) o Proxy Inverso municipal DEBE tener expresamente habilitado el tráfico WebSocket (protocolos ws:// y wss://). La reactividad de Shiny, el movimiento del mapa Leaflet y la validación de DNI dependen de este canal bidireccional continuo.
  • Dirección IP del Servidor: Asignación de una IP local fija/estática dentro de la red o DMZ municipal (ej. 192.168.10.50 o VLAN de servidores).
  • Puertos de Red:
    • Puerto Interno 3838 (TCP): Utilizado por el motor R Shiny para escuchar peticiones de la red local o proxy inverso.
    • Puerto Externo 443 (HTTPS / TCP): Acceso público seguro cifrado hacia los ciudadanos.
    • Puerto Externo 80 (HTTP / TCP): Redirección forzada automática a HTTPS.
  • Salida a Internet Saliente (Puerto 443): Permite la descarga en tiempo real de los mosaicos de mapas base satelitales (OpenStreetMap y Esri World Imagery) y la sincronización con el túnel seguro.

2.4 Estructura de Archivos, Permisos y Almacenamiento

Para mantener la seguridad del servidor según las buenas prácticas de la Contraloría y Gobierno Digital:

  • Usuario de Ejecución sin Privilegios: La aplicación debe ejecutarse bajo un usuario de servicio sin permisos de superusuario/administrador (ej. usuario shiny en Linux o cuenta de servicio dedicada en Windows).
  • Permisos de Solo Lectura (Read-Only):
    • app.R, carpeta R/ (lógica del sistema).
    • Carpeta data/ (Shapefiles oficiales inmutables aprobados por Ordenanza).
    • Carpeta www/ (estilos CSS, imágenes institucionales).
  • Permisos de Lectura y Escritura (Read-Write):
    • Exclusivamente sobre la carpeta outputs/: necesaria para registrar la bitácora de auditoría seudonimizada (control_acceso.log) y el estado temporal de sesiones ciudadanas (usuarios_sesion.rds).

2.5 Requisitos de Identidad Digital y Dominio Institucional

  • Subdominio Gubernamental Oficial: Creación de un registro DNS tipo pdu.munianta.gob.pe o geovisor.munianta.gob.pe administrado por la municipalidad (Punto.pe / PCM).
  • Certificado Digital SSL/TLS: Certificado de seguridad vigente emitido para el dominio (Let's Encrypt o certificado comercial TLS 1.2 / 1.3) para asegurar el candado de navegación segura.
  • Alternativa sin IP pública: Si la municipalidad no dispone de IP pública estática o puertos abiertos, se puede emplear el conector oficial Cloudflare Zero Trust (gratuito) para enlazar el dominio municipal directamente con el servidor sin exponer la red interna a ataques.

2.6 Procedimiento de Entrega del Paquete de la Aplicación

Para transferir el GeoVisor al servidor municipal, la OTI puede emplear cualquiera de estos dos canales oficiales:

  1. Opción Git (Recomendada para Actualizaciones Frecuentes): 
    git clone https://github.com/antapat/pdu_anta_2024_2034.git /srv/shiny-server/pdu_anta
    Permite actualizar capas o normativas en el futuro con un simple git pull.
  2. Opción Paquete Cerrado (Despliegue Aislado / Offline): Copiar la carpeta raíz completa pdu_anta_2024_2034 en la unidad del servidor, preservando íntegras las subcarpetas data/, R/, www/ y docs/.

3. Opción A: Servidor en la Municipalidad (Windows 10 / 11 / Server)

Esta opción aprovecha una computadora dedicada dentro de la oficina de la Gerencia de Desarrollo Urbano y Rural (GDUR), sin pagar mensualidades por servicios en la nube.

Paso 3.1: Configuración de Energía y BIOS

  1. Suspender la suspensión del equipo: En Windows, ir a Configuración > Sistema > Energía y batería y configurar "Al estar enchufado, suspender el equipo tras:" en NUNCA.
  2. Auto-encendido tras corte eléctrico (BIOS): Reiniciar el equipo, entrar al BIOS (tecla F2 o Supr) y en la pestaña Power Management activar "Restore on AC Power Loss" > Power On. Con esto, si se corta la luz en la municipalidad, la máquina se prenderá sola apenas regrese el suministro.

Paso 3.2: Ejecución Continua como Servicio de Windows (NSSM)

Para que el visor arranque automáticamente incluso si ningún usuario inicia sesión en Windows, se utiliza el gestor libre NSSM (Non-Sucking Service Manager): 

# 1. Descargar nssm.exe en la carpeta del proyecto
# 2. Abrir PowerShell como Administrador e instalar el servicio:
nssm.exe install GeoVisorAnta "C:\Program Files\R\R-4.6.1\bin\x64\Rscript.exe" "run_server.R"
nssm.exe set GeoVisorAnta AppDirectory "D:\pdu_anta_2024_2034"
nssm.exe set GeoVisorAnta Start SERVICE_AUTO_START
nssm.exe start GeoVisorAnta
Autonomía 100%: Con este servicio configurado, el motor de Shiny permanecerá corriendo en el puerto local 3838 en segundo plano de forma silenciosa y permanente.

4. Opción B: Servidor Cloud Linux (Ubuntu Server 22.04 / 24.04 LTS)

Es el estándar de excelencia para portales institucionales de alto tráfico. Puede contratarse en cualquier proveedor de hosting en la nube (DigitalOcean, AWS, Hetzner, o servidores del Estado Peruano / GORE Cusco).

Paso 4.1: Instalación de Dependencias Espaciales

# Actualizar repositorios e instalar librerías geoespaciales C++
sudo apt update && sudo apt upgrade -y
sudo apt install -y software-properties-common dirmngr gnupg apt-transport-https
sudo apt install -y gdal-bin libgdal-dev libgeos-dev libproj-dev libudunits2-dev libssl-dev

# Instalar R base y desarrollo
sudo apt install -y r-base r-base-dev

Paso 4.2: Instalación de Shiny Server

# Descargar y desplegar Shiny Server Open Source
wget https://download3.rstudio.org/ubuntu-18.04/x86_64/shiny-server-1.5.22.1017-amd64.deb
sudo gdebi shiny-server-1.5.22.1017-amd64.deb

# Clonar el proyecto en el directorio del servidor
cd /srv/shiny-server
sudo git clone https://github.com/antapat/pdu_anta_2024_2034.git pdu_anta
sudo systemctl enable shiny-server
sudo systemctl start shiny-server

5. Opción C: Contenedores Docker (Portabilidad Total)

Permite empacar todo el GeoVisor (código, capas shapefile, entorno R y dependencias del sistema operativo) en una imagen inmutable. 

# Archivo: Dockerfile
FROM rocker/geospatial:4.4.0

RUN install2.r --error --skipinstalled \
    shiny bslib leaflet sf DT RColorBrewer htmltools scales

WORKDIR /app
COPY . /app

EXPOSE 3838
CMD ["Rscript", "run_server.R"]

Para ponerlo en marcha en cualquier computadora o servidor del mundo basta un solo comando: 

docker build -t geovisor-anta .
docker run -d --name geovisor-live --restart always -p 3838:3838 geovisor-anta

6.1 Enlace Gratuito Mediante GitHub Pages (Implementado Actualmente)

Es el método que acabamos de configurar con éxito:

  • Dirección Oficial Permanente: https://antapat.github.io/pdu_anta_2024_2034/

6.2 Enlace con Dominio Propio Institucional (Ej. pdu.munianta.gob.pe)

Si la municipalidad desea un subdominio oficial .gob.pe:

  4. Instalar el servicio permanente en Windows con el token asignado: 
    tools\cloudflared.exe service install [TOKEN_PROVISTO_POR_CLOUDFLARE]

7. Respaldo y Cumplimiento Legal

En estricto cumplimiento de la Ley N° 29733 (Ley de Protección de Datos Personales del Perú) y la Directiva de Seguridad R.D. N° 019-2013-JUS/DGPDP:

Privacidad por Diseño (Privacy by Design): El GeoVisor NO almacena números de DNI en texto claro. Todo registro en outputs/usuarios_sesion.rds y outputs/control_acceso.log se realiza mediante un código seudonimizado (Hash SHA-256 criptográfico con Salt de sistema).

Procedimiento Periódico de Mantenimiento

  • Respaldo de Cartografía: Copiar la carpeta data/ a un disco externo o almacenamiento seguro cada vez que se emita una actualización de la zonificación por Ordenanza Municipal.
  • Respaldo de Auditoría: El archivo outputs/control_acceso.log registra el historial de visitas para estadísticas municipales. Debe archivarse anualmente por la GDUR.
  • Actualización de Capas: Si se aprueba una modificación urbana, solo se reemplazan los archivos Shapefile en data/ y se reinicia el servidor R. El visor actualizará instantáneamente las capas sin alterar la configuración del servidor.

8. Blindaje Integral de Ciberseguridad y Mitigación de Vulnerabilidades (SEC-01 a SEC-05)

En el marco del proceso de auditoría y hardening del GeoVisor del PDU de Anta, se implementaron controles técnicos avanzados para neutralizar cinco (5) vectores de riesgo de seguridad, en cumplimiento del marco normativo nacional establecido por el Centro Nacional de Seguridad Digital (CNSD / PCM) y la Ley N° 29733 (Ley de Protección de Datos Personales del Perú).

8.1 Vulnerabilidad SEC-05: Políticas de Enmarcado y Mitigación de Clickjacking (CWE-1021)

El Vector de Ataque y Amenaza:

Si el servidor no define de forma estricta las políticas de procedencia de marcos (frame-ancestors en Content Security Policy), portales fraudulentos o actores maliciosos podrían incrustar el GeoVisor en páginas falsas (phishing) mediante etiquetas <iframe>. De esta forma, simularían la imagen institucional de la Municipalidad Provincial de Anta para capturar números de DNI de los ciudadanos o realizar ataques de Clickjacking (superposición de elementos transparentes para engañar al usuario).

Blindaje Implementado en Cuatro (4) Capas Complementarias (Defensa en Profundidad):

Capa 1: Reverse Proxy Nginx (Archivo Oficial deploy/nginx/geovisor_anta.conf)

Se inyectan encabezados HTTP estrictos a nivel de protocolo web antes de que cualquier contenido sea transmitido al navegador: 

# Restringe la incrustación únicamente al portal de GitHub Pages y subdominios municipales
add_header Content-Security-Policy "frame-ancestors 'self' https://antapat.github.io https://*.munianta.gob.pe;" always;

# Impide ataques de adivinación de tipo MIME (MIME Sniffing)
add_header X-Content-Type-Options "nosniff" always;

# Protección de privacidad en el encabezado Referrer
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Política de permisos de periféricos (Solo autoriza geolocalización GPS oficial)
add_header Permissions-Policy "geolocation=(self 'https://antapat.github.io'), microphone=(), camera=()" always;

Capa 2: Borde Cloudflare Zero Trust (Archivo deploy/cloudflare/config.yml)

Para la transmisión mediante túnel cifrado (Cloudflare Tunnel), las peticiones provenientes de sitios de terceros no autorizados son filtradas en la red perimetral (Edge) de Cloudflare antes de tocar el servidor municipal.

Capa 3: Motor R Shiny y Validación Activa de Origen en Cliente (app.R / run_server.R)

En el propio código de la aplicación se ejecuta una doble salvaguarda:

  • Encabezados Nativos HTTP en R: Mediante shinyOptions(httpResponseHeaders = list(...)), el servidor httpuv emite directamente la política de procedencia de marco.
  • Frame Busting Activo en JavaScript: Si la aplicación se carga dentro de un iframe, un script en tags$head comprueba el origen del documento padre (document.referrer). Si no proviene de antapat.github.io ni *.munianta.gob.pe, destruye de inmediato el DOM (impidiendo mostrar el formulario de DNI o el mapa) y redirige al portal oficial.

Capa 4: Portal Contenedor en GitHub Pages (docs/index.html)

El portal institucional en GitHub Pages incorpora defensas anti-enmarcado para asegurar que la propia portada no pueda ser incrustada en portales fraudulentos externos. Si se detecta un intento de enmarcado no autorizado, la página rompe el marco y se abre a pantalla completa oficial (window.top.location.href = window.self.location.href).

8.2 Matriz Consolidada de Seguridad y Mitigaciones Implementadas

Código Vulnerabilidad Identificada Severidad Mitigación Técnica Aplicada en el Código
SEC-01 Bypass de Control de Acceso en Servidor (CWE-306) Alta En app.R se blindaron los eventos reactivos de consulta territorial (gps_location_device, btn_consultar_punto, btn_consultar_poligono) con validación estricta de sesion_vigente(). Si la sesión expiró o no se validó DNI, la consulta se rechaza y se cierra la sesión en el servidor.
SEC-02 Sal Criptográfica Pública y Fija en Código (CWE-327) Media En R/mod_acceso_dni.R se eliminó la sal estática pública. Ahora se genera dinámicamente un secreto criptográfico único de 256 bits almacenado en outputs/.pdu_secret_key (ignorado por Git) o en variable de entorno PDU_PEPPER_KEY, cumpliendo con la Ley N° 29733.
SEC-03 Agotamiento de Memoria y Fuga de Temporales (CWE-400 / CWE-459) Media En app.R se implementaron directivas on.exit(unlink(temp_dir, recursive = TRUE, force = TRUE)) para borrar inmediatamente los archivos Shapefile subidos y se estableció un límite máximo de 1,000 vértices por polígono para prevenir bloqueos de GEOS.
SEC-04 Exposición de Información en Repositorio Público (CWE-200) Informativa Se estableció la arquitectura definitiva de desacoplamiento: en producción, los datos espaciales y el motor R Shiny se alojan exclusivamente en el servidor físico o cloud municipal de la OTI, manteniendo en GitHub Pages únicamente el archivo estático ligero docs/index.html.
SEC-05 Clickjacking y Suplantación en Iframes (CWE-1021) Alta Implementación en profundidad de la política frame-ancestors 'self' https://antapat.github.io https://*.munianta.gob.pe; en Nginx, Cloudflare Tunnel, Shiny Server y validación activa de origen en JavaScript con bloqueo instantáneo del DOM.

8.3 Archivos de Configuración de Seguridad Provistos para la OTI

En la carpeta deploy/ y la raíz del repositorio se han integrado los archivos de configuración listos para producción:

  • deploy/nginx/geovisor_anta.conf: Configuración completa de Nginx con SSL/TLS, WebSockets y encabezados CSP (SEC-05).
  • deploy/cloudflare/config.yml: Configuración del agente cloudflared para túnel seguro.
  • deploy/systemd/geovisor-pdu-anta.service: Archivo de servicio Linux Systemd con sandboxing y reinicio automático ante fallos.
  • deploy/postgres/init_pdu_sesiones.sql: Script SQL oficial para inicializar la base de datos PostgreSQL/PostGIS transaccional ACID (CWE-362).
  • .Renviron.example: Plantilla de variables de entorno con las credenciales de conexión de base de datos municipal.
